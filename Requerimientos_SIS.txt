# Sistema de Reservas / Citas — Requerimientos

## Descripción General
API backend para gestionar reservas de citas entre clientes y profesionales que ofrecen servicios con duración y precio definidos. El sistema debe evitar solapamientos de horario y diferenciar permisos según el rol del usuario.

---

## Roles de Usuario

| Rol | Descripción |
|---|---|
| **Admin** | Gestiona profesionales, servicios y tiene visibilidad total de citas |
| **Profesional** | Define su disponibilidad, ve y gestiona sus propias citas |
| **Cliente** | Consulta disponibilidad, crea y cancela sus propias citas |

---

## Entidades (atributos requeridos, no estructura de tablas)

**Usuario**
- nombre, correo, contraseña, rol, fecha de registro

**Servicio**
- nombre, descripción, duración (minutos), precio, activo/inactivo

**Profesional**
- vinculado a un usuario
- lista de servicios que ofrece
- horario disponible (días y rangos de hora)

**Cita**
- cliente, profesional, servicio, fecha y hora de inicio, fecha y hora de fin (calculada), estado

**Estado de la Cita** (valores posibles)
- pendiente, confirmada, cancelada, completada

---

## Reglas de Negocio (Validaciones obligatorias)

1. No se puede crear una cita en una fecha/hora pasada.
2. No se puede crear una cita fuera del horario disponible del profesional.
3. No se puede crear una cita que se solape con otra cita ya existente del mismo profesional.
4. La duración de la cita la determina el servicio seleccionado, no el usuario.
5. Solo el cliente que creó la cita o un admin puede cancelarla.
6. Una cita cancelada no debe poder pasar a "completada".
7. Un servicio inactivo no debe aparecer como opción disponible para nuevas citas.
8. Un profesional no puede ofrecer un servicio que no esté en su lista asignada.

---

## Funcionalidades por Rol

**Cliente**
- Ver lista de servicios disponibles
- Ver disponibilidad de un profesional en un rango de fechas
- Crear una cita
- Ver sus propias citas
- Cancelar una cita propia (antes de cierto límite de tiempo, a definir)

**Profesional**
- Definir/actualizar su horario disponible
- Ver sus citas asignadas
- Marcar una cita como completada
- Cancelar una cita propia

**Admin**
- CRUD completo de servicios
- CRUD completo de profesionales
- Ver todas las citas del sistema
- Cancelar cualquier cita

---

## Endpoints Requeridos (funcionalidad, no implementación)

**Autenticación**
- Registro de usuario
- Login (devuelve token)

**Servicios**
- Listar servicios activos
- Crear / editar / desactivar servicio (admin)

**Profesionales**
- Listar profesionales (filtrable por servicio)
- Crear / editar profesional (admin)
- Definir horario disponible (profesional)

**Disponibilidad**
- Consultar slots libres de un profesional en una fecha dada

**Citas**
- Crear cita
- Listar citas propias (según rol)
- Cancelar cita
- Marcar cita como completada (profesional/admin)

---

## Requerimientos No Funcionales

- Autenticación basada en token (JWT)
- Diferenciación de permisos por rol en cada endpoint sensible
- Respuestas de error claras cuando una validación de negocio falla (no solo error 500 genérico)
- Confirmación de cita debe poder notificarse sin bloquear la respuesta del endpoint
- Documentación automática de la API (Swagger/OpenAPI vía FastAPI)
